# Lab 07: 문제를 진단하고 복구하기 (선택)

⏱ **예상 시간:** 30분 (시간이 부족하면 생략 가능)
🎯 **이 랩에서 배우는 것**
- 실제 오류 증거(Events, Pod 상태, 이미지 참조)만으로 원인을 판단하는 방법
- 승인 후 복구하는 흐름

## 왜 이 랩이 필요한가요?

실제 운영에서 문제는 항상 생깁니다. 중요한 것은 "그럴듯한 추측"이 아니라 **증거 기반 진단**입니다. 이 랩은 강사가 준비한 제한된 오류(잘못된 이미지 태그) 하나만 다룹니다.

## 시작 전에 확인하세요

- [Lab 06](06-run-sample-workload.md)의 정상 상태 증거가 있나요?
- 강사가 이 랩의 장애 주입을 승인했나요?

## Step 1. 증거로 원인 분석하기

**사용 Skill:** `azure-diagnostics`

```text
azure-diagnostics를 사용해 lab namespace의 샘플 Deployment가 준비되지 않는 원인을 읽기 중심으로 분석해줘. Events, Pod 상태, 이미지 참조를 근거로 원인을 제시하고 영향 범위와 복구 변경을 설명한 뒤 적용 승인 전에는 멈춰.
```

## Step 2. 승인 후 복구하고 재검증하기

복구 변경(예: 올바른 이미지로 되돌리기)을 승인한 뒤 적용하고, [Lab 06](06-run-sample-workload.md)의 계층별 확인을 다시 수행합니다.

> ⚠️ **주의:** 권한 확대, IP 제한 완화, namespace 삭제는 복구 수단이 아닙니다.

## ✅ 완료 체크리스트

- [ ] 원인을 실제 증거(Events/Pod 상태)로 설명함
- [ ] 복구 변경을 승인 후 적용함
- [ ] 재검증으로 정상 상태를 다시 확인함

## 🚧 문제가 생겼다면

| 증상 | 원인일 가능성 | 해야 할 일 |
| --- | --- | --- |
| 원인이 불명확 | 증거 부족 | Events와 Pod describe 결과를 더 수집 |
| 복구 후에도 실패 | 다른 근본 원인 존재 | 강사에게 에스컬레이션 |
