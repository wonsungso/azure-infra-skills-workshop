# Lab 05: AKS 배포하고 접속 확인하기

⏱ **예상 시간:** 45분
🎯 **이 랩에서 배우는 것**
- 승인된 배포를 실제로 실행했을 때 무엇을 확인해야 하는지
- Entra 인증 기반 접속과 최소 권한이 실제로 동작하는지 검증하는 방법

## 왜 이 랩이 필요한가요?

배포 명령이 "성공"이라고 응답해도, 실제로 노드가 Ready 상태가 되고 참가자가 허용된 범위 내에서만 접속할 수 있는지는 별도로 확인해야 합니다. 이 랩에서는 배포 대기 시간을 포함해 실제 상태를 관찰합니다.

## 시작 전에 확인하세요

- [Lab 04](04-validate-and-approve.md)의 배포 승인이 있나요?

## Step 1. 클러스터 배포 관찰하기 (25분)

**사용 Skill:** `azure-enterprise-infra-planner`

```text
승인된 계획을 대상으로 azure-enterprise-infra-planner의 배포 단계를 진행해줘. 배포 진행 상태와 생성된 자원을 기록하고, 실패하면 실제 오류를 분류해줘. 승인 범위를 벗어난 변경은 하지 마.
```

배포는 시간이 걸립니다(보통 여러 분). 기다리는 동안 [Lab 06](06-run-sample-workload.md)의 manifest를 미리 읽어볼 수 있지만, 실제 성공 여부는 클러스터가 Ready 상태가 된 뒤에만 판단합니다.

> 💡 **Tip:** 예비 클러스터(강사가 데모용으로 준비한 것)를 보게 되더라도, 그것이 우리 팀의 배포 성공을 의미하지 않습니다.

## Step 2. Entra 접속과 최소 권한 확인하기 (20분)

**사용 Skill:** `azure-resource-lookup`

```text
azure-resource-lookup을 사용해 [aks-name]의 실제 상태와 node resource group을 읽기 전용으로 확인해줘. 이후 Entra 기반 참가자 접속을 확인하는 데 필요한 점검 항목을 제시해줘. 역할을 변경하지 마.
```

**당신이 실제로 확인할 것**
- 노드가 Ready 상태인가?
- 강사가 bootstrap한 `lab` namespace에 쓰기가 허용되는가?
- 다른 namespace에는 쓰기가 거부되는가? (이것도 반드시 확인해야 할 성공 조건입니다)

> ⚠️ **주의:** 접속이 안 될 때 허용 IP 목록을 스스로 넓히지 않습니다. 강사에게 실제 출구 IP와 전파 지연 여부를 확인하세요.

## ✅ 완료 체크리스트

- [ ] 클러스터가 실제로 Ready 상태임을 확인
- [ ] `lab` namespace 쓰기 허용을 확인
- [ ] 다른 namespace 쓰기 거부를 확인
- [ ] 위 결과를 증거 로그에 기록

## 🚧 문제가 생겼다면

| 증상 | 원인일 가능성 | 해야 할 일 |
| --- | --- | --- |
| 배포가 정책/쿼터 오류로 실패 | 리전 용량 부족, 정책 위반 | 강사에게 즉시 보고, 대체 리전/SKU 논의 |
| API 서버 접속 불가 | 허용 IP 미반영 또는 전파 지연 | 몇 분 대기 후 재시도, 강사에게 IP 확인 요청 |
| `lab` namespace 접근 거부 | 강사 bootstrap 미완료 | 강사에게 namespace/권한 부여 완료 여부 확인 |
