# Lab 03: 인프라 계획 승인받고 Bicep 만들기

⏱ **예상 시간:** 55분
🎯 **이 랩에서 배우는 것**
- 설계 결정을 실제로 "승인 가능한 계획 문서"로 만드는 과정
- 승인된 계획을 Bicep 코드로 구체화하는 과정

## 왜 이 랩이 필요한가요?

`azure-enterprise-infra-planner` Skill은 요구사항을 정리해서 계획을 만들고, 사람이 승인하면 그제서야 실제 코드(Bicep)를 생성합니다. **"계획 → 승인 → 코드 생성"** 순서를 지키는 것은 나중에 잘못된 자원이 배포되는 것을 막는 핵심 안전장치입니다.

## 시작 전에 확인하세요

- [Lab 02](02-design-aks.md)의 Day-0 결정표와 권한 매트릭스가 있나요?

## Step 1. 인프라 계획 만들고 승인하기 (35분)

**사용 Skill:** `azure-enterprise-infra-planner`

[계획 프롬프트](../../prompts/workshop-prompts.md#계획)를 사용하세요.

**진행 방식**
1. 프롬프트를 실행하면 에이전트가 대안, 위험, 예상 비용 요인을 정리해서 보여줍니다.
2. 팀원들과 함께 내용을 검토합니다. 특히 다음을 확인하세요.
   - 기존에 이미 있는 자원(예: 강사가 미리 만든 VNet)은 "참조"만 하고 다시 만들지 않는지
   - API 허용 IP, Entra 인증, local accounts 비활성화가 빠짐없이 포함됐는지
3. 팀에서 승인자를 한 명 정하고, 승인 여부를 명확히 말로 표현합니다(예: "이 계획을 승인합니다").

> ⚠️ **주의:** 계획을 승인하기 전에는 다음 Step으로 진행하지 않습니다. 애매하면 질문을 더 하세요.

**완료 기준:** `.azure/infrastructure-plan.json`(또는 동등한 계획 산출물)이 생성되고, 승인자와 승인 시각이 기록됩니다.

## Step 2. 승인된 계획으로 Bicep 생성하기 (20분)

**사용 Skill:** `azure-enterprise-infra-planner`

```text
승인된 infrastructure plan과 공통 입력표를 읽어 Bicep을 생성 또는 갱신해줘. 기존 foundation 자원은 참조하고, 변경 대상과 생성 파일을 설명해줘. 검증과 배포는 아직 하지 마.
```

**당신이 확인할 것**
- 생성된 파일 목록과 위치
- 매개변수(허용 IP, CIDR, SKU 등)가 계획과 정확히 일치하는지

> 💡 **Tip:** 참고용으로 [강사용 Bicep 기준본](../../reference/infra/main.bicep)을 열어볼 수 있지만, 이건 비교용이지 그대로 복사해서 쓰는 용도가 아닙니다.

## ✅ 완료 체크리스트

- [ ] 계획이 승인되고 승인자/시각이 기록됨
- [ ] Bicep 파일이 생성되고 계획과 일치함
- [ ] 아직 `az deployment` 등 실제 배포 명령은 실행하지 않음

## 🚧 문제가 생겼다면

| 증상 | 원인일 가능성 | 해야 할 일 |
| --- | --- | --- |
| 계획에 없던 자원이 생성 목록에 있다 | 기존 자원 참조가 누락됨 | "기존 자원은 참조만" 문구를 강조해 재요청 |
| 매개변수가 계획과 다르다 | 입력표 값이 최신이 아님 | 입력표를 갱신하고 재생성 요청 |
| 승인자가 불명확하다 | 팀 역할 미정 | Lab 01의 역할 정리로 돌아가기 |
