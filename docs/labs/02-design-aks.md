# Lab 02: AKS 설계 결정하기 — 네트워크, 노드풀, 권한

⏱ **예상 시간:** 45분
🎯 **이 랩에서 배우는 것**
- AKS를 만들기 전에 결정해야 하는 것들(운영 모드, 네트워크, 노드풀, 접근 제어)
- Skill의 도움을 받아 "누가 무엇을 할 수 있는지" 최소 권한으로 정리하는 방법

## 왜 이 랩이 필요한가요?

AKS는 한 번 만들고 나면 바꾸기 어려운 설정(네트워크 플러그인, CIDR 등)이 많습니다. 그래서 "만들기 전에" `azure-kubernetes` Skill로 Day-0 결정을 검토하고, `azure-rbac` Skill로 "누가 무엇을 할 수 있는지"를 미리 표로 정리합니다. 이 랩은 아직 아무것도 만들지 않는 **설계 단계**입니다.

## 시작 전에 확인하세요

- [Lab 01](01-orientation-and-setup.md)에서 scope 확인을 마쳤나요?
- 공통 입력표에 리전과 리소스 그룹이 채워져 있나요?

## Step 1. AKS Day-0 결정 검토하기 (25분)

**사용 Skill:** `azure-kubernetes`

```text
azure-kubernetes를 사용해 [aks-name] 교육용 AKS의 Day-0 선택을 검토해줘. Standard 운영 모드, system/user pool 분리, Azure CNI Overlay + Cilium, load balancer egress, public API authorized IP ranges를 기준으로 대안과 위험을 표로 정리해줘. 리소스 변경은 하지 마.
```

**이 단계에서 사람이 판단할 것**
- system pool 2개 + user pool 1개 구성이 교육 목적에 맞는지 (운영 환경의 고가용성 구성이 아님을 이해)
- Pod CIDR, Service CIDR, DNS 서비스 IP가 서로 겹치지 않는지
- API 서버를 공개하되 허용 IP 목록으로만 제한한다는 것의 의미

> 💡 **Tip:** SKU나 실제 사용 가능한 용량은 이 Skill이 추측하지 않습니다. 리허설에서 강사가 확정한 값만 입력표에 반영하세요.

> ⚠️ **주의:** "허용 IP 목록을 넓히거나 없애면 더 쉽지 않을까?"라는 제안이 나오면 승인하지 않습니다. 이 워크샵은 공개 API + 허용 IP 제한을 기본 보안 경계로 삼습니다.

## Step 2. 최소 권한 매트릭스 만들기 (15분)

**사용 Skill:** `azure-rbac`

```text
azure-rbac을 사용해 이 교육용 AKS의 최소 권한 매트릭스를 작성해줘. Azure 리소스 배포자, 역할 할당자, AKS control-plane managed identity, lab namespace 참가자를 분리하고 scope와 필요한 작업을 표로 보여줘. 권한을 변경하지 마.
```

**왜 역할을 이렇게 나누나요?** "리소스 그룹을 만들 수 있는 권한"과 "다른 사람에게 역할을 부여할 수 있는 권한"은 다릅니다. 그리고 "Azure 리소스를 배포할 수 있는 권한"과 "Kubernetes 안에서 Pod를 만들 수 있는 권한"도 완전히 다른 시스템입니다. 이 표를 만들어 두면 나중에 "왜 안 되지?"라는 질문에 바로 답할 수 있습니다.

**당신이 확인할 것**
- 참가자에게 구독 Owner나 cluster-admin을 부여하는 제안이 없는지
- 실제 권한 부여(bootstrap)는 이 랩에서 하지 않고 강사가 나중에 수행한다는 것을 이해했는지

## ✅ 완료 체크리스트

- [ ] Day-0 결정표(네트워크/노드풀/접근)를 팀 전체가 이해했다
- [ ] 미결정 항목이 있다면 강사에게 확인했다
- [ ] 최소 권한 매트릭스를 증거 로그에 연결했다
- [ ] 아직 Azure에 아무것도 생성하지 않았다

## 🚧 문제가 생겼다면

| 증상 | 원인일 가능성 | 해야 할 일 |
| --- | --- | --- |
| CIDR 겹침 경고 | 팀 간 CIDR 재사용 | 강사에게 팀 전용 CIDR 재배정 요청 |
| SKU를 Skill이 추측함 | 리허설 확정값을 프롬프트에 안 넣음 | 입력표 값을 다시 채워서 재요청 |
| 권한 매트릭스에 Owner/cluster-admin이 등장 | 프롬프트 누락 또는 잘못된 제안 | 최소 권한 원칙을 다시 언급하며 재요청 |
